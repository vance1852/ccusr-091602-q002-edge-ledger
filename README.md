# 边缘遥测可信账本

工业边缘网关在**断网缓存补传、PLC 时钟漂移、序号回绕、双网关碰撞、服务重启**
下产生的遥测，不能只给消费者“一条洗平的曲线”。本服务为每条设备原始序号建立
幂等边界，区分五类入账结果，保留每一次归一化所采用的时钟模型与测点配置，并让
已封存的生产窗口不可变——迟到数据只生成带血缘的修订版。

纯 Python 标准库实现，无外部依赖；状态以追加式 JSONL WAL 持久化，重启确定性重放。

## 运行

```bash
python -m unittest discover -s tests -v     # 41 项测试
python -m demo.run_incident                 # 现场事故端到端演示
python -m demo.run_incident --wal run.jsonl # 保留 WAL 供复查
```

## 判定边界（对应 `domain_contract.json`）

| verdict             | 触发条件                                                        | 是否产生唯一事件 |
|---------------------|-----------------------------------------------------------------|------------------|
| `accepted`          | 指纹首次出现、序号落入新槽位（含乱序补入仍开放的窗口）           | 是               |
| `duplicate`         | 指纹已存在——同网关重发或双网关冗余转发同一份采样都归此          | 否（留转发痕迹） |
| `late`              | 指纹首次出现，但事件时间落入**已封存**窗口                      | 是（生成修订版） |
| `sequence_conflict` | 同 `代际/循环/序号` 槽位已有**不同指纹**的采样（双网关碰撞）    | 否（双方报文留证）|
| `quarantined`       | 报文无法解释（缺字段、NaN/Inf、不可解析）                       | 否（原始载荷留证）|

指纹 = SHA256(设备 + 代际 + 序号 + 测点 + 值 + 设备时间)。**刻意不含网关**：
两个网关冗余转发同一采样判重复；同序号却声称不同载荷才判碰撞。碰撞不做静默覆盖，
胜方（先到）成为事件，败方进冲突台账，双方原始报文均可调阅。

### 乱序 vs 迟到

- **乱序**：报文接收顺序颠倒，但事件窗口仍开放 → `accepted`（标注
  `arrival-out-of-order`），按事件时间插入。
- **迟到**：事件时间所属窗口已封存 → `late`，封存版本不动，追加 `revised` 版本。

### 序号回绕与代际

序号按设备配置的模数（如 16 位即 65536）展开为服务端**线性序号**。回绕判定不
只看序号大小（断网补传时小序号本来就晚到），必须同时满足：已见序号越过半程、
当前序号落入前半程、**设备时间继续向前**。设备换代（`gen` 递增）另起循环空间，
新旧代际槽位互不冲突。检测到的序号缺口登记为 `Gap`（含按实测采样节奏估算的
事件时间区间），补传到达后闭环；网关重连时 `resume` 游标会列出待补序号。

## 时间质量与时钟模型（`time_quality`）

校时记录（NTP/现场控制台/设备重同步）按服务器时间登记，每条归一化记录都冻结
所采用的 `clock_model_id`，可回溯“为什么这个事件时间是这个值”：

- `device`：无任何校时记录，设备时钟原样采用；
- `corrected`：两条校时记录之间**分段线性插值**，或按校时点偏差/频偏**外推**；
- `estimated`：读数落在重同步后的**校准沉淀窗口**（设备时钟可能刚跳变，归属存疑），
  以及纯外推区间（另附 `time-correction-extrapolated` 标注）；
- `unknown`：报文缺设备时间，用网关接收时间兜底（最低可信度）。

插值模型表达为两锚点间的一条直线（模型 ID 相同、各点瞬时偏差不同），因此多个
事件可复用同一模型 ID 而不丢失各自的修正依据。

## 测点配置版本

移机、量程板更换、校准参数变更都登记为**带生效事件时间**的配置版本
（`PointConfig.effective_event_time`）。解释读数按**事件时间**选择当时生效的版本，
不是按注册时间或当前配置——新配置永不改写历史读数。目录缺失的测点原值透传，
标记为 `raw/unknown`。

## 窗口封存与版本血缘

固定时间窗口（默认 60s）有三种状态：`open → sealed → revised`。

- `seal_window` / `seal_due` 把开放工作副本冻结为不可变 **v1**（含事件集、
  count/min/max/mean、按事件时间归属的峰值、缺口快照、时钟模型与配置版本清单）；
- 迟到数据进入已封存窗口时，基于父版本生成 **v2..n**，记录
  `parent_version`、`introduced_event_ids`、`affected_metrics`；
- v1 永远可回放。**峰值归属按事件时间定序**，接收顺序的颠倒不会再颠倒峰值。

## 持久化与重启

`LedgerStore` 只追加一个 JSONL WAL，事实类型为 `cal / config / message /
quarantine / seal`。入账支持显式逻辑时间戳，重启时按原始顺序重放，指纹、线性
序号、循环、缺口、窗口版本、entry/event 编号全部逐位重建（无需状态迁移）。

## 代码结构

| 模块                    | 职责                                                     |
|-------------------------|----------------------------------------------------------|
| `app/model.py`          | 原始报文、指纹、时钟/校准/配置值对象、归一化记录、缺口、窗口版本、入账条目 |
| `app/clock.py`          | 校时记录登记、插值/外推/沉淀期的时钟模型决策             |
| `app/config.py`         | 按事件时间生效的测点配置版本与工程量解释                 |
| `app/ledger.py`         | 幂等/碰撞/序号/缺口判定，窗口封存与修订，游标与回放查询   |
| `app/persistence.py`    | 追加式 WAL 与重启确定性重放                              |
| `app/service.py`        | 面向网关与消费者的服务门面（报文校验、登记、查询、审计）  |
| `demo/run_incident.py`  | 断网补传→回绕→双网关碰撞→重启的端到端事故演示            |
| `tests/`                | 判定、序号、时钟、配置、查询、持久化、场景、服务共 41 项  |

## 典型查询

```python
svc.resume("gw-a")                          # 重连续传游标 + 待补缺口
svc.replay_window(win_id, version=1)        # 回放封存的旧版本
svc.replay_range("devA", "temp", t0, t1)    # 按事件时间回放（各窗最新版）
svc.explain(event_id)                       # 单事件完整证据链：原始报文+时钟依据+配置+冲突
svc.lineage(win_id)                         # 窗口版本血缘与受影响指标
svc.gaps("devA", "temp")                    # 缺口台账（open/resolved、估算时间）
svc.conflicts("devA")                       # 双网关碰撞台账
svc.audit_trail()                           # 全部入账判定轨迹（含重复/冲突/隔离）
```
